# 장애 조사 기록

실제 장애의 조사 과정을 순서대로 기록한 문서입니다. 구조 설명 문서는 현재 코드 구조를 설명하고, 이 폴더는 그 구조를 선택한 이유를 기록합니다. 결론만 남기면 이후 담당자가 복잡한 코드를 단순하게 되돌릴 수 있으므로, 되돌리면 안 되는 이유를 조사 과정과 함께 기록합니다.

틀린 가설도 삭제하지 않고 함께 기록합니다. 다음 담당자가 같은 가설을 다시 검증하지 않도록 하기 위함입니다.

## 작성 방법

배포된 서버·앱에서 확인된 오류를 수정한 담당자는 수정과 같은 작업에서 기록을 추가하십시오. 원인이 자명한 오타·문구 수정은 기록 대상에서 제외합니다.

파일명은 `YYYY-MM-DD(제목).md`입니다. 제목은 명사형으로 작성하십시오. 같은 원인이 다시 발생하면 새 파일 대신 기존 기록에 재발 날짜를 추가하십시오.

구성은 다음과 같습니다. 증상과 원인 사이의 단계가 많을수록 `3. 조사 과정`이 길어집니다.

```text
1. 증상                 (+ 배경 지식: 처음 읽는 사람을 위한 설명)
2. 조사 난점
3. 조사 과정            (제외한 가설은 표로 정리)
4. 원인
5. 해결
6. 검증
7. 교훈
8. 같은 증상 재발 시 확인 순서
관련 코드
```

커밋 기록에서 재구성한 장애는 조사 과정이 남아 있지 않으므로 요약형으로 작성합니다. 구성은 증상, 원인, 해결, 재발 시 확인 순서, 관련 커밋입니다.
