# 문서 갱신 완료 확인

기능 변경 작업의 완료 조건에는 관련 문서 갱신이 포함입니다. 작업 완료를 보고하기 전에 아래 순서로 확인하십시오.

## 1. 바뀐 내용과 원본 문서 대조

`git diff --stat`으로 바뀐 파일을 확인하고 아래 표에서 함께 고칠 문서를 찾으십시오. 원본 위치는 사람용 문서 폴더의 `reference/document-locations.md`에 있습니다.

| 바뀐 내용 | 함께 확인할 문서 |
|---|---|
| API 요청·응답·오류·권한 | API 원본, 연동 안내, 관련 예제 |
| 화면·사용 흐름·로딩·오류 처리 | 화면 설명, 사용 방법, 필요 시 런북 |
| 도메인 규칙·DB 구조·마이그레이션 | 도메인 설명, 데이터 문서, 적용 절차 |
| 환경변수·실행 명령·빌드·배포 | 설정 목록, 로컬 실행 안내, 배포 절차 |
| 운영 동작·장애 대응·복구 | 런북, 관측·복구 절차 |
| 파일 위치·작업 순서·검사 명령 | 관련 README, `AGENTS.md`, AI 참고 파일 목록 |

- 기존 문서를 먼저 수정하십시오. 새 파일은 기존 문서에 맞지 않는 내용일 때만 추가하십시오.
- 같은 설명을 AI용 문서에 복사하지 마십시오. AI용 문서는 원본으로 연결합니다.
- 배포된 서버·앱의 오류를 고쳤다면 장애 조사 기록 폴더에 기록을 추가하십시오.

## 2. 문서 검사

`docs.config.json`이 있는 저장소 루트에서 실행하십시오. 허브의 코드 저장소에서 작업했다면 문서 저장소에서 실행하십시오.

```bash
python3 scripts/check_docs.py --write-catalog
python3 scripts/check_docs.py
python3 scripts/check_docs.py --workspace   # 허브만
```

devdog 플러그인이 있으면 바뀐 문서에 문체 검사도 실행하십시오.

```bash
python3 <devdog 플러그인>/scripts/kolint.py <바뀐 문서>
```

## 3. 보고

완료 보고에 다음을 포함하십시오.

- 갱신한 문서 경로
- 실행한 검사 명령과 결과. 실행하지 못한 검사는 이유와 함께 구분
- 문서 변경이 필요 없다면 그 이유
- 접근 제한으로 갱신하지 못한 문서는 미완료 항목과 필요한 조치

문서를 갱신하지 않은 상태를 작업 완료로 보고하지 마십시오.
