# 플러그인 있음·없음 비교

같은 작성 요청을 플러그인 있음·없음 두 조건으로 실행하고 결과 파일을 비교한 기록입니다. 실행 스크립트는 [ablation.py](ablation.py), 요청 목록은 [cases.json](cases.json)입니다.

## 실행 조건

| 항목 | 값 |
|---|---|
| 실행일 | 2026-09-24 |
| 모델 | Sonnet (`--model sonnet`) |
| 케이스 | 런북, 커밋 메시지, 코드 주석, 번역투 문단 수정 4종 |
| 반복 | 케이스·조건별 2회, 총 16회 |
| 설정 격리 | `--setting-sources project,local` (사용자 전역 CLAUDE.md·설치 플러그인 제외) |
| 비용 | 없음 조건 $0.44, 있음 조건 $0.58 |

사용자 전역 설정에 같은 문체 규칙이 있으면 기준선이 오염됩니다. 그래서 두 조건 모두 사용자 설정을 제외했습니다. `--safe-mode`는 `--plugin-dir` 플러그인의 스킬·훅도 비활성화하므로 사용하지 않았습니다.

## 결과

| 케이스 | 조건 | kolint error | kolint warn | 누락 사실 |
|---|---|---|---|---|
| runbook | 없음 | 2 | 0 | 0 |
| runbook | 있음 | 0 | 0 | 0 |
| commit | 없음 | 0 | 0 | 0 |
| commit | 있음 | 0 | 0 | 0 |
| comment | 없음 | 0 | 0 | 0 |
| comment | 있음 | 0 | 0 | 0 |
| rewrite | 없음 | 3 | 0 | 0 |
| rewrite | 있음 | 0 | 0 | 0 |

- 없음 조건의 위반은 런북 표 칸의 "~다" 종결 2건, 수정 문단의 해라체 2건과 부연 문장 1건입니다.
- 누락 사실은 요청에 넣은 숫자·명령·경로(케이스별 3~7개)가 결과에 없는 건수입니다. 두 조건 모두 0건입니다.

## 결과 글 비교 (rewrite 케이스)

| 항목 | 플러그인 없음 | 플러그인 있음 |
|---|---|---|
| 본문 말투 | "요청을 포기한다" (해라체) | "요청을 중단합니다" (합쇼체) |
| 어휘 | "값을 보유한 채" | "값을 보관한 채" |
| 부연 문장 | "동작은 이상이 전부이다." | 삭제 |
| 표 칸 | "아직 응답이 없는 상태" | "아직 응답을 받지 못함" |

## 해석과 한계

- 표본은 조건당 8회입니다. 통계적 결론이 아니라 동작 확인 수준의 결과입니다.
- 플러그인 있음 조건의 훅은 kolint로 위반을 찾아 수정을 요청합니다. 채점도 kolint로 하므로 kolint 위반 수는 플러그인에 유리한 지표입니다. 위의 결과 글 비교처럼 사람이 직접 비교한 결과를 함께 확인하십시오.
- 커밋·주석 케이스는 기준선도 위반이 없었습니다. Sonnet은 짧은 글에서 이미 명사형 커밋 제목과 완결 문장 주석을 작성했습니다.
- 첫 실행에서는 "이상이 전부이다"를 kolint가 검출하지 못했습니다. `filler` 규칙을 보강한 뒤 `--rescore`로 다시 채점했습니다.

## 재실행

```bash
python3 evals/ablation.py --runs 2 --model sonnet     # Claude 사용량 발생
python3 evals/ablation.py --rescore evals/results/ablation-<시각>.json
```
