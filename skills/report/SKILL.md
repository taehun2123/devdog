# PDF 보고서 작성

한국은행 경제전망보고서의 구성과 디자인을 기술 보고서에 적용하는 절차입니다. Claude가 Markdown 원문을 작성하고 `report.py`가 PDF로 변환합니다. 문장 규칙은 [devdog:writing](../writing/SKILL.md)을 따릅니다. 스크립트 경로는 이 스킬 폴더 기준 `../../scripts/`이며, 아래 명령의 `$K`는 그 폴더입니다.

## 필요 도구

- Python 3.8 이상. 표준 라이브러리만 사용합니다.
- Chrome, Edge, Chromium 중 1개. 자동으로 찾지 못하면 `--chrome` 또는 환경변수 `CHROME_PATH`로 실행 파일 경로를 지정하십시오.

## 보고서 구성

| 순서 | 구성 요소 | Markdown | 출력 |
|---|---|---|---|
| 1 | 표지 | 앞부분 `title`·`subtitle`·`org`·`code` | 남색 강조 막대, 제목, 발행 시기, 작성 조직 |
| 2 | 차례 | 자동 생성 | 단원·장·소제목·Box와 쪽 번호 |
| 3 | 핵심 전제 | `# 핵심 전제 {.front}` | `□ [키워드]` 문장과 `⇒` 결론 |
| 4 | 요약 | `# 요약 {.front}` + `::: summary` | 테두리 상자 안 핵심 문장과 요약표 |
| 5 | 단원 | `# 제목` | 회색 간지, 장 목차 |
| 6 | 장 | `## 제목` | `1.` 번호 제목, 새 쪽에서 시작 |
| 7 | 소제목 | `### 제목` | 남색 막대 소제목 |
| 8 | 번호 문단 | `**핵심 문장.** 근거` | `1-1.` 번호와 파란 굵은 핵심 문장 |
| 9 | 그림 | `::: figure` | 연속 2개 가로 배치, `[그림 1.1]` 번호 |
| 10 | 표 | `::: table` | 남색 머리행, `[표 1.1]` 번호 |
| 11 | 심화 설명 | `::: box`·`::: note` | `Box 1`·`참고 1` 테두리 상자 |
| 12 | 부록 | `# 부록 {.appendix}` | 차례에서 점선 아래 표시 |

문법 전체와 차트 JSON 형식은 [references/syntax.md](references/syntax.md), 전체 예시는 [examples/sample.md](examples/sample.md)에 있습니다.

## 작성 절차

1. 독자, 기간, 결론을 확인하십시오. 수치와 출처가 없는 항목은 사용자에게 요청하십시오. 수치를 추정해 채우지 마십시오.
2. 독자 범위를 정하십시오. 과제·제안서·외부 보고처럼 다른 사람에게 제출하는 문서에는 독자가 판단에 쓰는 정보만 작성하십시오. 다음 항목은 작성자 쪽 정보이므로 넣지 마십시오.
   - 예시 문서·이전 버전 대비 비교 표
   - 평가 기준(배점)별 대응 표
   - 팀 할 일 주석(예: `실습 시 확인`)
   - 독자가 정한 규정·일정의 반복(예: 제출 기한, 기말고사 주간)
   - 본문과 같은 내용의 그림·표 주석

   요약표의 비교 기준 열과 `다음 작업` 줄은 독자가 내부 팀일 때만 작성하십시오.
3. 말투를 정하십시오. 경제전망보고서 형식은 해라체(`~할 전망이다`)입니다. 보고서 폴더에 `.devdog.json`을 두고 `{"docRegister": "haera"}`를 설정하십시오. 저장소 문서와 같은 합쇼체를 쓰려면 설정하지 마십시오.
4. 배치를 정하십시오. 20쪽 이하 제출 문서는 앞부분에 `layout: compact`를 설정하십시오. 단원 간지 쪽과 장별 쪽 나눔을 생략해 내용이 절반 이하인 쪽 수를 감소시킵니다.
5. 요약을 먼저 작성하십시오. 요약의 `□` 문장은 본문 번호 문단의 핵심 문장과 같은 결론이어야 합니다.
6. 본문 번호 문단은 첫 문장에 결론 1개를 굵게 쓰십시오. 다음 문장에는 근거 수치, 비교 기준, 원인을 쓰십시오.
7. 그림은 주장 1개당 1개로 만들고 2개씩 연속 배치하십시오. 헤드라인에는 그림의 결론을 쓰고, 캡션에는 대상과 단위를 쓰십시오. 모든 그림과 표에 `자료:` 줄을 쓰십시오.
8. 전망치는 `e)` 표시나 차트 `shade` 음영으로 실적치와 구분하십시오. 이전 전망 대비 변화는 `[+0.1]`처럼 대괄호로 표시하십시오.
9. 불확실성이 큰 전망은 `### 시나리오 분석`에 기본·낙관·비관 시나리오와 시나리오별 수치 표를 작성하십시오.

## 생성과 검사

```bash
python3 $K/kolint.py report/                                  # 문체 검사
python3 $K/report.py report/report.md -o report/report.pdf    # PDF 생성
python3 $K/report.py report/report.md --html report.html      # Chrome 없이 HTML만 생성
```

PDF를 만든 뒤 Read 도구로 표지, 차례, 그림이 있는 쪽을 열어 확인하십시오. 확인 항목은 다음과 같습니다.

- 차례 쪽 번호와 실제 쪽 일치 여부
- 그림 축 범위 밖으로 나간 선이나 겹친 범례 여부
- 표가 쪽 경계에서 잘렸는지 여부
- `자료:` 누락 여부
- 내용이 절반 이하인 쪽 여부. 있으면 `layout: compact` 설정, 그림 폭 축소, 행이 많은 표 위치 변경 순서로 처리하십시오.
- 쪽 끝에 제목이나 표 제목만 남은 쪽 여부
- 마지막 쪽에 표나 그림 1개만 남은 여부
- 사진에 표시 상자를 그린 그림의 상자와 대상 위치 일치 여부

## 제한 사항

- 차례 쪽 번호는 PDF 뷰어의 쪽 번호와 같은 물리 쪽 번호입니다. 표지를 1쪽으로 셉니다.
- 각주는 쪽 하단이 아니라 해당 장의 끝에 모아 표시합니다.
- 머리행이 2단 이상인 표는 `::: table` 안에 HTML `<table>`로 작성하십시오.
- 차트는 선·막대·누적 막대·전망 음영만 지원합니다. 그 밖의 그림은 `image:`로 PNG·SVG 파일을 삽입하십시오.
