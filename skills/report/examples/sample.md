# 전망의 핵심 전제 {.front}

- **[트래픽]** 신규 기업 고객 유입으로 월간 요청 수가 증가세를 이어갈 전망이다. 다만 대형 고객 이전이 4분기에 마무리되면서 증가율은 점차 둔화될 것으로 예상된다.

⇒ 월간 요청 수 증가율은 3분기 12%에서 4분기 8% 수준으로 전제하였다. 이는 6월 전제 대비 2%p 상향 조정한 수준이다.

- **[인프라 비용]** 예약 인스턴스 계약이 10월에 갱신되면서 단위 요청당 비용이 하락할 것으로 가정하였다.

⇒ 요청 100만 건당 비용은 3분기 41달러에서 4분기 36달러로 전제하였다.

::: table 주요 전제
| 항목 | 전제 |
|---|---|
| 트래픽 | 월간 요청 수 증가율 3분기 12%, 4분기 8% |
| 인프라 비용 | 예약 인스턴스 갱신 후 요청 100만 건당 36달러 |
| 배포 | 주 2회 정기 배포 유지, 긴급 배포 월 2회 이하 |
자료: 플랫폼운영팀 내부 계획
:::

## 운영 여건

- 고객 기업 수는 3분기 중 38곳 증가하여 누적 412곳을 기록하였다.
- 외부 결제 대행사 API의 응답 지연이 8월 중 3회 발생하였다. 해당 구간의 재시도 정책을 9월에 변경하였다.

# 운영 현황 및 전망

## 주요 지표 점검

### 가용성

**3분기 서비스 가용성은 장애 대응 자동화 효과로 99.95%를 기록할 전망이다.** 7월 데이터베이스 주 노드 장애[^db] 이후 자동 장애 조치를 적용하였다. 이에 따라 평균 복구 시간이 42분에서 18분으로 단축되었다. 8월 이후 1시간 이상 지속된 장애는 발생하지 않았다.

**4분기에는 배포 횟수 증가에도 가용성이 99.96% 수준을 유지할 것으로 예상된다.** 카나리 배포 비율을 5%에서 10%로 조정하여 배포 실패의 영향 범위를 제한한다.

::: box 자동 장애 조치 적용 결과
**자동 장애 조치는 데이터베이스 주 노드의 응답이 30초 이상 없으면 대기 노드를 주 노드로 전환한다.** 전환 후 애플리케이션 연결 풀을 재생성하는 데 평균 40초가 소요되었다.

**적용 이후 2회의 노드 장애가 발생하였으며 모두 5분 이내에 복구되었다.** 수동 조치가 필요했던 7월 장애의 복구 시간은 42분이었다.
:::

### 성능

**API 응답 시간(p95)은 3분기 중 320ms로 2분기 대비 15% 단축되었다.** 조회 API의 캐시 적중률이 61%에서 78%로 상승한 결과이다.

::: table 주요 API 응답 시간

| 주문 조회 | 410 | 290 | −29.3 |
| 결제 승인 | 520 | 480 | −7.7 |
| 상품 검색 | 280 | 260 | −7.1 |
주: p95 기준
자료: APM
:::

## 전망의 리스크 평가

### 시나리오 분석

**대형 고객 이전 일정과 결제 대행사 응답 지연이 전망의 주요 불확실성 요인이다.** 두 요인에 대한 대안 시나리오를 설정하고 가용성과 비용에 미치는 영향을 점검하였다.

- **낙관 시나리오**에서는 대형 고객 이전이 10월 중 완료된다. 이 경우 4분기 요청 수가 기본 전망보다 6% 증가하고 단위 비용은 2달러 하락한다.
- **비관 시나리오**에서는 결제 대행사 응답 지연이 월 5회 이상 발생한다. 이 경우 결제 승인 API의 가용성이 99.90%까지 하락한다.

::: table 시나리오별 4분기 전망
| 구분 | 가용성(%) | 요청 100만 건당 비용(달러) |
|---|---:|---:|
| 기본 | 99.96 | 36 |
| 낙관 | 99.96 | 34 |
| 비관 | 99.90 | 37 |
:::

[^db]: 7월 14일 02시 10분부터 02시 52분까지 주문 데이터베이스 쓰기 중단
