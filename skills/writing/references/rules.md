# 한국어 공학 문서체 세부 규칙

이 문서는 규칙별 판단 기준과 수정 전후 예시입니다. 예시는 실제 서비스 문서·코드 주석을 정리하며 수정한 문장을 익명화한 것입니다. 규칙 ID는 `kolint.py` 검사 결과의 이름입니다.

## 1. 말투 (`register-mix`)

| 대상 | 기본 말투 | 설정 키 |
|---|---|---|
| 문서 설명 문장 | `~입니다`·`~합니다` | `docRegister: hapsyo` |
| 문서 절차 문장 | `~하십시오` | `docRegister: hapsyo` |
| 코드 주석 | 저장소 규칙 (예: `~한다`) | `commentRegister` |
| 커밋 제목 | 명사형 | `commitSubject: noun` |
| 커밋 본문 | 저장소 규칙 | 해당 없음 |

한 문서 안에서 `~이다`와 `~입니다`를 섞지 마십시오. 인용 블록(`>`)과 따옴표 안 원문은 원래 말투를 유지합니다.

| 수정 전 | 수정 후 |
|---|---|
| 커밋 히스토리에 남는다. | 이전 코드는 커밋 히스토리에서 확인할 수 있습니다. |
| 별도 어트리뷰션 서비스를 선정한 뒤 확장한다. | 별도 어트리뷰션 서비스를 선정한 뒤 확장합니다. |

## 2. 제목 (`heading-sentence`)

제목은 명사형으로 작성합니다. 다음 종결은 제목으로 쓰지 않습니다.

- 평서문: `~한다`, `~않는다`, `~이다`
- 의문문: `~인가`, `~는가`, `~까`, `?`, 의문사(무엇·왜·어떻게)로 끝나는 제목
- 조건·상황: `~때`, `~려면`, `~하면`
- 조사·연결어미: `~에`, `~에서`, `~으로`, `~하고`, `~해서`
- 목적: `~않게`, `~도록`

| 수정 전 | 수정 후 |
|---|---|
| 다섯 가지 상태를 나눠 준다 | 응답 상태 |
| `deps`가 바뀌면 앞의 답을 지운다 | `deps` 변경 시 이전 응답 초기화 |
| 재시도 중에 화면이 무엇을 그리는가 | 재시도 중 화면 표시 |
| 새 테스트를 어디에 둘까 | 새 테스트 위치 |
| 문서만 고친 커밋은 배포되지 않는다 | 문서 전용 커밋 미배포 |
| 되돌릴 때 | 롤백 기준 |
| 커밋 전에 | 커밋 전 확인 |

## 3. 표 칸과 목록 항목 (`table-cell-sentence`)

표 칸은 `~함`, `~음`, `~ 여부`, 명사구로 끝냅니다. `~다`로 끝나는 문장을 쓰지 않습니다. 여러 문장으로 된 설명 칸(런북 조치 등)은 본문과 같은 말투를 사용합니다. 예시 문장을 보여 주는 열(머리행이 "수정 전", "표현", "메시지" 등)은 검사하지 않습니다.

| 수정 전 | 수정 후 |
|---|---|
| 아직 답이 없다 | 아직 응답을 받지 못함 |
| 한 번 실패했지만 포기하지 않았다 | 실패 후 재시도 |
| 한다 / 안 한다 | 재시도 / 재시도 안 함 |
| GHCR에 있습니다 | GHCR에 보관 |
| 다시 계산하면 두 진실이 생긴다 | 다시 계산하면 서버 값과 달라짐 |
| 몇 분 기다립니다 | 수 분 대기 |

## 4. 비유·의인화·일상어 (`metaphor`)

사람·신체·생물에 빗댄 표현과 대화체 동사를 기술 용어로 바꿉니다. 대응표는 [glossary.md](glossary.md)에 있습니다.

| 수정 전 | 수정 후 |
|---|---|
| 서버가 답을 안 주고 소켓만 붙잡고 있다. | 업스트림이 응답하지 않고 소켓 연결만 유지한다. |
| 여기서 죽으면 앱이 안 뜬다. | 여기서 예외가 발생하면 앱이 기동하지 않는다. |
| 실패를 조용히 삼키지 않는다. | 실패를 무시하지 않는다. |
| 전국 행정구역표를 클라이언트에 박아 두지 않는다. | 전국 행정구역표를 클라이언트에 하드코딩하지 않는다. |
| 서버에서 다시 읽는다. 실패하면 들고 있던 값을 그대로 둔다. | 서버에서 다시 조회한다. 실패하면 보관 중인 값을 유지한다. |
| 테스트가 버그를 잡는다. | 이 테스트로 버그를 검출한다. |

무생물 주어에 사람의 행위 동사를 붙이지 않습니다. 주어를 사람·시스템으로 바꾸거나 "~하면 ~된다", "~로 확인한다"로 작성합니다.

### 순우리말 동작 동사 (`native-verb`)

동작을 기술할 때 순우리말 동사 대신 한자어 기술 동사를 사용합니다. 대응표는 [glossary.md](glossary.md)에 있습니다.

| 수정 전 | 수정 후 |
|---|---|
| 높이는 하한만 둔다. | 최소 높이만 설정한다. |
| 띠 높이를 글자 크기만큼 늘린다. | 띠 높이에 글자 확대율을 적용해 확대한다. |
| 라벨을 알아볼 수 없을 만큼 줄였다. | 라벨이 판독 불가 크기로 축소되었다. |
| 줄높이가 상자 높이를 넘는다. | 줄높이가 상자 높이를 초과한다. |

### 읽기 어려운 번역어 (`plain-term`)

번역어·전문어는 독자가 바로 이해하는 표현으로 바꿉니다. 대응표는 [glossary.md](glossary.md)에 있습니다.

| 수정 전 | 수정 후 |
|---|---|
| 대화 목록 전체가 크래시했습니다. | 채팅 목록 화면 전체가 강제 종료됐습니다. |
| 방은 표시되지만 전송이 차단됐습니다. | 채팅방은 표시되지만 메시지가 전송되지 않았습니다. |
| 사용 위치에서 `!`로 존재를 단언했습니다. | 사용 위치에서 `!`로 필수 조건을 걸었습니다. |
| 단언 위치에서 오류가 발생했습니다. | 필수 조건을 건 위치에서 오류가 발생했습니다. |

## 5. 부연 문장 (`filler`)

앞 문장이나 표로 이미 전달한 내용을 반복·강조하는 문장은 삭제합니다.

| 수정 전 | 수정 후 |
|---|---|
| 이게 전부입니다. 서버 응답은 하나도 저장하지 않습니다. | 서버 응답은 저장하지 않습니다. |
| 여기서 점수를 매기면 두 번 세는 셈이 된다. | 여기서 점수를 계산하면 중복 집계된다. |
| 실패를 "없어요"로 말하면 없는 사실을 지어내는 셈입니다. | 조회 실패를 "없어요"로 표시하면 사실과 다른 정보가 됩니다. |

"이것이 핵심입니다", "같은 값을 두 번 받는 셈입니다"도 같은 유형입니다.

## 6. 긴 대시 (`em-dash-aside`)

긴 대시로 조건·이유·예외를 덧붙이지 않습니다. 다음 문장이나 별도 항목으로 나눕니다. 숫자 범위(`00–24시`)와 목록 기호는 해당하지 않습니다.

| 수정 전 | 수정 후 |
|---|---|
| 서버가 카카오 로컬 API를 대신 부른다 — REST 키가 앱 번들에 박히면 안 된다. | 카카오 로컬 API는 서버가 대신 호출한다. REST 키를 앱 번들에 포함하면 안 되기 때문이다. |
| 대화방 맥락 제목 — 친선전 카드의 제목으로 쓴다. | 대화방 맥락 제목. 친선전 카드의 제목으로 사용한다. |

## 7. 조사 띄어쓰기 (`particle-spacing`)

영문 단어, 코드 스팬, 숫자 뒤 조사는 붙여 씁니다.

| 수정 전 | 수정 후 |
|---|---|
| `ChatMessageKind` 는 두 가지입니다. | `ChatMessageKind`는 2가지입니다. |
| 클라이언트가 S3 에 직접 올립니다. | 클라이언트가 S3에 직접 업로드합니다. |

## 8. 문장 구성

- 본문은 완결 문장으로 작성합니다. "의도, 끝 조건, 하지 않을 것."처럼 명사만 나열한 문장은 쓰지 않습니다.
- 한 문장에는 한 가지 정보만 씁니다. `~고`, `~는데`, `~서`로 문장을 길게 잇지 않습니다.
- 영문 직역 표현과 불필요한 명사화를 피합니다.

| 피할 표현 | 고친 표현 |
|---|---|
| 작업별 원문과 검증 근거를 제공합니다 | 작업에 필요한 문서와 확인할 코드의 목록입니다. |
| 문서의 단일 진입점을 구성합니다 | 문서를 찾을 때 처음 열 파일은 README입니다. |
| 최신성을 보장하기 위한 갱신 트리거 | 문서를 함께 고쳐야 하는 변경 |

## 9. 커밋 메시지

커밋 메시지는 `git log` 목록에서 확인하는 기록입니다. 한 줄만 읽고 변경 대상과 이유를 알 수 있어야 합니다.

```text
fix(auth): 토큰 갱신 실패 오류 수정

- 만료 7일 전 갱신 요청이 401로 거절되던 원인 제거
- 리프레시 토큰 만료 임박 시 재발급
```

### 제목 (`commit-subject`)

- 형식은 `type(scope): 명사형 요약`입니다. `수정`·`추가`·`제거`·`변경`·`분리`·`표시`·`허용`·`차단` 같은 동작 명사로 끝냅니다.
- `~한다`, `~했다`, `~합니다`, 해요체, 마침표로 끝내지 않습니다.
- 버그 수정 제목은 `<대상> <증상> 오류 수정` 형식으로 대상과 증상을 포함합니다.
- 화면과 코드에서 쓰는 이름을 그대로 사용합니다. 모양을 풀어 쓰거나 비유로 바꾸지 않습니다.

| 이렇게 | 이렇게 말고 |
|---|---|
| `fix(matching): 상단바와 목록 렌더링 겹침 오류 수정` | `fix(matching): 펴진 상단이 목록 내용을 덮던 것을 고친다` |
| `feat(queue): 빠른 매칭 시간 조건에 대기 인원 표시` | `feat(queue): 빠른 매칭 시간 조건에도 대기 인원을 표시한다` |
| `refactor(auth): 소셜 로그인 응답 생성을 공통 컴포넌트로 분리` | `refactor(auth): 소셜 로그인 응답 생성을 하나로 뽑아낸다` |

### 본문 (`commit-body-separator`, `commit-body-style`)

- 본문은 필요할 때만 작성합니다. 제목과 본문 사이에 빈 줄 1개를 삽입합니다.
- 본문에는 변경 이유와 영향을 적습니다. 변경 내용 자체는 디프로 확인할 수 있으므로 반복하지 않습니다.
- 제목과 같은 톤의 짧은 개조식으로 작성합니다. 항목 끝을 `~다`, `~습니다`, 해요체로 끝내지 않습니다.
- 한 커밋에 논리적 변경이 여러 개 섞이면 커밋을 나눕니다.

| 이렇게 | 이렇게 말고 |
|---|---|
| `- 쿼리 수 200회에서 6회로 감소` | `- 쿼리 수를 줄였습니다.` |
| `- 셀프호스트 러너에서 캐시 업로드만 325초 소요` | `- 캐시 업로드가 너무 오래 걸렸다` |

저장소 규칙이 완결 문장 본문이면 `.devdog.json`의 `commitBody`를 `any`로 설정합니다.

### 금지 항목 (`commit-file-list`, `commit-signature`, `commit-emoji`, `commit-trailer`)

- 파일 목록이나 함수 이름을 나열하지 않습니다. 예: `fix: RecruitmentServiceImpl.java 수정`.
- `Co-Authored-By: Claude …`, `🤖 Generated with …` 같은 AI 도구 서명과 공동작업 표기를 넣지 않습니다.
- 유니코드 이모지를 쓰지 않습니다.
- 작성자 이름과 날짜를 본문에 적지 않습니다. 커밋 메타데이터에 이미 기록됩니다.
- 그 밖에 저장소가 금지한 트레일러는 `forbidTrailers` 설정으로 검사합니다.

### PR (`pr-title`, `pr-signature`, `pr-emoji`)

- PR 제목은 커밋 제목과 같은 명사형 요약입니다.
- PR 본문은 커밋 본문과 같은 톤의 개조식으로 변경 이유와 확인 방법을 적습니다. Markdown 제목과 표는 문서 규칙을 따릅니다.
- `🤖 Generated with Claude Code` 같은 AI 도구 서명과 이모지를 넣지 않습니다.

## 10. 코드 주석

- 주석의 말투는 저장소 규칙을 따릅니다. 규칙이 없으면 파일 안의 기존 주석과 맞춥니다.
- 비유·의인화·부연 규칙은 문서와 같습니다.
- 이미 적용된 DB 마이그레이션 파일(예: Flyway SQL)의 주석은 수정하지 않습니다. 주석도 체크섬에 포함되어 운영 서버 기동이 실패할 수 있습니다.
- 주석만 고치는 작업에서는 코드 줄을 바꾸지 않습니다. 수정 후 컴파일·타입 검사를 실행합니다.

### 항목 형식 (`comment-narrative`)

주석은 서술형 문단 대신 명사형 제목과 `- 라벨: 내용` 항목으로 구성합니다. 항목 없이 `~다` 문장이 3개 이상인 주석 블록은 `comment-narrative`로 검출합니다.

- 첫 줄은 명사형 제목입니다.
- 항목 라벨 예: 값, 대상, 기준, 원인, 방식, 주의, 참고
- 한 줄 주석은 `// 대상 동작 (조건): 목적` 형태로 작성합니다. 예: `// 중첩 스크롤 설정 (Android): 외부 스크롤의 드래그 선점 방지`
- 수정 경위와 과거 수치("16으로 설정했을 때 숫자가 잘렸다")는 커밋 메시지에 기록합니다. 주석에는 현재 코드의 기준과 이유를 기록합니다.

수정 전:

```ts
/*
 * 탭 높이는 하한만 둔다. 고정 높이에서 글자를 확대하면 줄높이가 안쪽 높이를 넘고,
 * 안드로이드가 높이에 맞추려고 라벨을 알아볼 수 없을 만큼 줄였다.
 * 그래서 최소 높이만 지정한다.
 */
```

수정 후:

```ts
/*
 * 탭 최소 높이 설정
 * - 원인: 확대 줄높이가 내부 높이 초과
 * - 고정 높이 사용 시 Android adjustsFontSizeToFit의 라벨 과도 축소
 */
```
