# 한국어 공학 문서체

개발 조직의 한국어 문서, 커밋 메시지, 코드 주석을 정확하고 일관되게 작성하기 위한 규칙입니다. 목표는 문장이 자연스러운 것보다 독자가 사실·조건·절차를 한 번에 찾는 것입니다.

## 최우선 원칙: 의미 보존

문체를 고칠 때 숫자, 식별자, 코드 스팬, 조건, 예외, 원인, 날짜를 삭제하거나 바꾸지 마십시오. 부연 문장을 지울 때는 그 문장이 새 정보를 담고 있지 않은지 먼저 확인하십시오. 표현을 바꾸다가 사실이 바뀌면 원문을 유지하는 편이 낫습니다.

## 요소별 규칙

| 요소 | 규칙 | 예 |
|---|---|---|
| 문서 설명 문장 | `~입니다.` 합쇼체 | 캐시는 5분 동안 유지됩니다. |
| 절차 문장 | `~하십시오.` | 설정 파일을 확인하십시오. |
| 제목 | 명사형. 문장·의문문·"~때"·조사 종결 금지 | "다섯 가지 상태를 나눠 준다" → "응답 상태" |
| 표 칸·목록 항목 | "~함"·"~음"·명사구 종결 | "아직 답이 없다" → "아직 응답을 받지 못함" |
| 커밋 제목 | `type(scope): 명사형 요약` | "fix: 로그인 오류를 고쳤다" → "fix(auth): 토큰 갱신 실패 오류 수정" |
| 커밋 본문 | 빈 줄 뒤 변경 이유를 짧은 개조식으로 작성 | "토큰 갱신 로직을 고쳤습니다." → "- 만료 임박 토큰 재발급 누락 원인 제거" |
| PR 제목·본문 | 커밋과 같은 규칙, 본문은 개조식 Markdown | "🤖 Generated with Claude Code" 삭제 |
| 코드 주석 | 저장소 규칙의 말투, 명사형 제목과 `- 라벨: 내용` 항목, 비유 금지 | 3문장 서술 → "탭 최소 높이 설정" + "- 원인: 확대 줄높이가 내부 높이 초과" |

저장소에 `.devdog.json`이나 문서 규칙 파일이 있으면 그 설정이 우선합니다.

## 문장 규칙

1. 비유·수사를 쓰지 마십시오. 사실과 수치로 작성하십시오.
2. 코드·서버·테스트를 사람처럼 행동하는 주어로 쓰지 마십시오. "테스트가 버그를 잡는다" 대신 "이 테스트로 버그를 검출한다"로 작성하십시오.
3. 일상어 대신 기술 용어를 사용하십시오. "답" → "응답", "들고 있다" → "보관", "띄우다" → "표시", "부르다" → "호출".
   동작 동사는 한자어 기술 동사를 사용하십시오. "둔다" → "설정한다", "늘린다" → "확대한다", "줄인다" → "축소한다", "넘는다" → "초과한다".
4. 순우리말 풀어쓰기 대신 통용 외래어를 사용하십시오. 커밋, 머지, 리뷰, 스펙, 훅, 핫픽스.
5. 한 문장에는 한 가지 정보만 쓰십시오. 연결어미로 문장을 길게 잇지 마십시오.
6. 긴 대시(`—`)로 부가 설명을 붙이지 마십시오. 다음 문장이나 별도 항목으로 나누십시오.
7. "이게 전부입니다", "~하는 셈입니다"처럼 정보를 더하지 않는 문장은 지우십시오.
8. 횟수·날짜·수치로 작성하십시오. "여러 번" 대신 "3회"로 작성하십시오.
9. 영문 식별자·코드 스팬 뒤 조사는 붙여 쓰십시오. "`status` 는" → "`status`는".

세부 기준과 전후 예시는 [references/rules.md](references/rules.md), 용어 대응표는 [references/glossary.md](references/glossary.md)에 있습니다. 판단이 필요할 때만 읽으십시오.

## 작성 후 검사

글을 쓴 뒤 제목, 표 칸, 주석, 커밋 제목과 본문을 다시 확인하십시오. 커밋 메시지와 PR에는 파일 목록, 이모지, AI 도구 서명(`Co-Authored-By: Claude`, `🤖 Generated with` 등)을 넣지 마십시오. 결정적 검사기는 이 스킬 폴더 기준 `../../scripts/kolint.py`입니다.

```bash
python3 <플러그인 경로>/scripts/kolint.py docs/ README.md      # 문서·주석 검사
python3 <플러그인 경로>/scripts/kolint.py --commit-msg msg.txt  # 커밋 메시지 검사
```

검사기가 보고한 위치만 고치고, 보고되지 않은 문장은 바꾸지 마십시오. `metaphor`·`native-verb`·`comment-narrative`·`particle-spacing`·`em-dash-aside`는 warn 등급입니다. 문맥상 원래 뜻(예: 실제 그림 그리기)이면 유지하고, 필요하면 `kolint-disable-line` 주석으로 제외하십시오.

기존 저장소 전체를 전환하는 작업은 `devdog:migrate` 스킬의 절차를 따르십시오.
